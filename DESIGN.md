# Arcana interface

The workspace serves card discovery and deck editing. Issue [#9](https://github.com/RuneBrix/magic-the-deckbuilder/issues/9) established a collector’s index: warm paper, forest-green ink, crisp rules and restrained square controls. The shared header, dedicated deck editor and library in issues [#16](https://github.com/RuneBrix/magic-the-deckbuilder/issues/16), [#17](https://github.com/RuneBrix/magic-the-deckbuilder/issues/17) and [#18](https://github.com/RuneBrix/magic-the-deckbuilder/issues/18) extend this visual world. Card imagery remains complete and uncropped.

## Typography and icons

Self-hosted Newsreader gives headings and the wordmark an editorial character. Public Sans carries controls and dense deck rows. Font licenses and provenance live in public/fonts/. Headings use moderate weight and tracking no tighter than -0.025em. Body copy names concrete tasks, with no decorative slogans.

Authored SVGs share a 24-unit grid, 1.7-unit stroke and rounded joins. The overlapping card mark contains a diamond; the search lens repeats that diamond. Functional plus, close, transfer and help symbols retain familiar shapes. Icons accompany labels or accessible names.

## Focus and disclosure

The explorer identifies card search directly, with a secondary Track deck selector, one editable permanently labeled Scryfall query, Search and Clear search and filters, followed by collapsed Filters and Browse by function. The ordinary results heading leads into optional function starting searches or clearly separated loading/no-match/error/populated states. Sorting is permanently labeled beside searched results, not the initial state. Competing welcome headings and decorative icons are removed. Issues [#21](https://github.com/RuneBrix/magic-the-deckbuilder/issues/21), [#22](https://github.com/RuneBrix/magic-the-deckbuilder/issues/22) and [#23](https://github.com/RuneBrix/magic-the-deckbuilder/issues/23) extend the retained discovery interface. The effective query lives in the primary input; the former lower query disclosure is replaced by secondary query-only help. Open disclosure state survives search and deck rerenders.

Filters groups permanently labeled fieldsets for multiple card types/subtypes with all/any matching, two mana-value comparisons with all/any matching, separate card-color and color-identity modes, name and Oracle phrases, mana-cost containment, minimum literal symbol counts and independent format legality. Color modes distinguish exact, all, any, only selected colors including colorless, multicolor and colorless; minimum symbols distinguish colorless {C} from generic mana and permit requirements such as two {U}. Multicolor/colorless modes disable unused color checkboxes. Help stays beside the relevant controls, with fine rules separating families.

Typing the primary query updates supported guided controls without replacing the input or moving its cursor. Guided text and numbers stage the same query while typed; control changes or form submission run results. Matching choices persist through singleton and unused criteria so choosing Any before a second value keeps that intent. Query-only help exposes unsupported, complex or negated source expressions verbatim; affected guided controls are disabled with an explanation, while independent controls remain available. Incomplete syntax pauses requests and guided edits. This is a bounded projection; Scryfall remains the search authority. Completed results keep their source context and explicitly say when they belong to the previous query. Clear resets to the initial state and cancels pending responses; deliberate Search on a blank input visibly becomes `game:paper`. Scope, normalization boundaries and examples are in `docs/UNIFIED_SEARCH.md`.

Browse by function is subordinate to the card query: its smaller Find a function input has a permanent label and a quiet underline. The browser searches the dated Scryfall Oracle Tags snapshot by name and alias. Visible labels distinguish curated starting points, the full catalog, matching tags and recorded relationships; result counts and snapshot provenance live in secondary help. Results appear in batches of 30 with specific next-batch labels. Each tag has visibly distinct Add filter / Remove filter and Related actions; browsing broader/narrower links moves focus to the detail heading without changing the card query. Selected functions and their all/any choice remain outside the browser disclosure as removable query filters. Enter an existing Scryfall tag searches existing tagging data and does not create public taxonomy; outside-snapshot entries retain explicit uncertainty. The catalog provenance and update procedure are in `docs/TAG_TAXONOMY.md`.

Compare alternatives is a secondary native disclosure after results. Compare controls on results and card details select two cards; selection moves focus to the comparison heading. A semantic table keeps mana, colors, full Oracle text and search/role context aligned, including on phones. Ignore-condition buttons remove only a representable independent query condition, preserve query-only expressions, show both queries and the reason, and offer Return to original search with the exact original query. Relaxation and restoration move focus to results after completion. Searches do not remove comparison selections. Scope and interpretation are documented in `docs/EFFECT_COMPARISON.md`. [#20](https://github.com/RuneBrix/magic-the-deckbuilder/issues/20) simplifies the results hierarchy while retaining comparison behavior; candidate-list discovery in [#24](https://github.com/RuneBrix/magic-the-deckbuilder/issues/24) remains separate.

The shared horizontal header contains Explore cards, My decks and Settings, with compact browser-local save status and Help. My decks remains visibly selected in both the library and its editor; the editor identifies it as the current location. Settings opens a dialog for appearance and complete workspace JSON backup/restore. Deck import/export stays with its deck.

The dedicated editor leads with the deck name, format, playing-deck and sideboard counts, and labeled color identity. Find cards to add is the primary action; rename/format and import, export, duplicate and confirmed deletion remain secondary. Cards separates Main deck, Sideboard and Command zone with individual counts. Rows expose quantities, card names, mana costs, zone selectors and copy controls. Type or primary-function grouping, no grouping, name/mana-value/quantity ordering, and type/all-role filters stay above the rows. Primary function uses the first existing ordered personal role tag; every assigned role remains filterable, with no new role schema. Zone moves preserve all copies and merged roles. Inspect opens full details by keyboard or touch; desktop hover/focus previews keep the complete portrait. Playing-deck progress and Statistics exclude the sideboard. Commander decks label command-zone identity and explicitly show when no commander is designated; other decks label main-deck identity. My decks uses restrained bordered cards with complete card portraits, deck names, formats, labeled identity, summary statistics and Open deck. Management actions wrap below a fine divider. New deck and Import deck lead the library. Creation permits an incomplete deck and optional commander designation; designation adds one command-zone copy and does not certify eligibility or pairings. Rename/format, independent duplication, text import and text/complete per-deck JSON export are available in the library and editor. Delete names the deck in a confirmation dialog and initially focuses Keep deck. Text export states its metadata losses; JSON preserves the complete deck. See `docs/DECK_WORKSPACE.md` for behavior and limits.

## Layout and states

Every surface uses the same top header without a duplicate navigation sidebar. The editor and library occupy the main width within a centered 1200px maximum. Wide discovery optionally pairs a flexible explorer with a sticky compact tracker. Its left edge supports pointer resizing and keyboard Left/Right/Home/End; preferred width is 280–480px, capped at 40vw. At 960px that panel enters document flow with a named jump shortcut; the resize separator is hidden. Hidden/no-deck tracking releases the panel column. At 600px the header wraps its navigation onto a second horizontal row, keeping the brand and compact save status above it. Editor actions stack or wrap, four filter/group/order controls become two columns, and rows place mana and zone controls below the name while retaining adjacent copy controls. The library grid adapts to available width and becomes one column on phones. Discovery retains two card columns and a fixed deck shortcut. Expanded text filters stack vertically; settings actions wrap or stack. Dialogs stay within the viewport and preserve native focus containment and Escape dismissal.

Use small radii for controls and generous separation between work areas. Card images preserve portrait proportions and their existing brief hover lift; reduced-motion preferences suppress transitions and animations. Native details/summary controls expose state and keyboard activation. All controls retain visible keyboard focus. Loading, empty, error, disabled and storage-warning states use the same theme tokens.

Expanded discovery filters use a two-column grid of fieldsets on desktop and one column at 600px and below. Each mana comparison pairs its operator and value; minimum-symbol inputs retain a compact two-column grid. Color labels wrap, query-only source text breaks within the available width, and selected-function matching controls wrap with their labels. Function chips keep their filter action separate from Related on narrow screens. Preserve the primary query's stronger visual weight than the subordinate function lookup.

Parser/workspace regression checks are separate from visual review. The Impeccable engine/detector remained unavailable; macOS/Safari remain untested.
