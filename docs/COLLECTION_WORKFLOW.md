# Collection workflow

Implemented in [PR #86](https://github.com/RuneBrix/magic-the-deckbuilder/pull/86).

## Upload

Choose a TXT/CSV file or paste text. Syntax validation runs locally; no lookup occurs until Upload is pressed. Choose Add copies (default) or Replace entire inventory. Valid data enables Upload. The import checks all rows before showing a summary with the ready copy count and counts by issue category. Finish import applies the staged copies. Abort import discards them. Add shows uploaded and resulting total quantities; a separately opened upload intentionally adds again, including identical files. There is no content-based duplicate-file detection. A completed operation cannot apply twice; retry/resume of an unapplied operation reuses completed lookups and applies once. Closing/reloading discards upload progress.

Replace shows current copies/lots and uploaded copies, offers Save current workspace copy, and requires explicit replacement confirmation. Replacement requires every row to be valid collection data; skipped lines must be corrected or removed. Matching printing/finish/condition rows merge within the uploaded inventory; current lots are replaced, not combined. Both modes validate and persist the entire staged workspace before swapping live inventory. An unresolved workspace storage warning blocks upload until recovery, protecting unreadable saved data. Failed writes, unresolved/malformed data, cancellation and stale responses retain prior inventory and decks; corrected retries remain available. Decks, deck prices and independent price refresh are preserved. Complete workspace JSON retains selected printings, finishes and conditions; standalone collection export and broader interchange are not added.

Quantity/name text accepts card rows such as `2 Sol Ring`. Deck zone headings and invalid lines are listed under “Could not process the following cards”; confirm skipping them to upload valid rows. Lists are limited to 5000 card rows and 15 MB.

CSV accepts Quantity/Qty, Name/Card Name, Finish/Foil, Condition, Language/Lang Edition/Set Name or Code, and Collector Number. Quantity and Name are required. Unrecognized columns such as purchase price/tags are named as not counted and require explicit confirmation before upload. CSV with unrecognized required headings opens column mapping with suggested recognized fields and a first-row-as-headings control. Change CSV columns lets users correct a detected mapping before uploading. Duplicate/conflicting relevant mappings, malformed quotes, invalid values and unequal row widths block upload. Quoted commas, escaped quotes and duplicate card rows work.

Normal maps to internal regular and Scryfall nonfoil; common finish booleans, condition abbreviations and language names/codes normalize. Omitted finish prefers nonfoil among compatible printings; when the identified printing supports only foil or etched, use its supported finish. Omitted condition remains unrecorded. Text/CSV examples are separate, labeled and subdued; placeholders use muted italic styling. The editable textarea starts empty.

Matching printing/finish/condition rows add quantities; language is preserved by printing ID. Set, language, finish and collector number constrain printing resolution when supplied. A collector number requires a set. If several compatible remote printings share one rules identity and no collector number is given, use the lowest collector number. A uniquely matching stored printing can be reused. Upload resolves edition codes and normalized names through the Scryfall set catalog. Unknown sets, no matches and ambiguous results identify the CSV row and the field to correct. Unspecified printings use compatible stored/default facts; foil-only defaults trigger alternate lookup. Full double-faced names can use a validated front-face fallback. The former three-card Aang example passed live lookup; the current upload test can be explicitly rerun with `ARCANA_LIVE_CSV=1` and the `live localhost upload` filter in a disposable VM.

## Resolve upload issues

After lookup, the summary groups unresolved rows by printing, language, finish or card name. The app checks the exact name in a separate batch when edition constraints leave no compatible printing. Resolve errors guides the user through one row at a time. For a verified rules identity, choose a paper printing, language and finish from that card’s catalog. An unidentified name cannot be substituted; explicitly skip the row or abort. The final summary reports skipped rows and the copies to be added or used for replacement. More than 20 unresolved rows in any one category blocks manual resolution and shows the category counts so the source file can be corrected.

## Efficiency and cooldown

Use the [card lookup and import verification cases](DEVELOPMENT.md#card-lookup-and-import-verification) when changing Collection lookups, upload review or applying staged copies.

Reuse compatible cards from the collection, decks and a bounded session cache, indexed by full and face names. Only unresolved names enter 75-name batches; set/language rows skip redundant default lookup and share searches of up to 20 constrained terms. The client reads all pages in each batch and rechecks each row’s name, set, language, finish and collector number before selecting a printing. Duplicate alternate searches and successful batches remain cached in the open dialog. The upload shows the current amount of work and card being resolved. Failures clear active progress and leave a persistent error with a recovery action.

The server shares a paced queue across endpoints, waits at least 600 ms after each upstream request, coalesces identical pending lookups and caches responses for five minutes. A 429 blocks queued/new requests for at least 60 seconds or longer Retry-After. Resume upload requires an explicit action after cooldown. Other processes on the same IP are outside this queue. The [dated import research](archive/COLLECTION_IMPORT_RESEARCH.md) preserves source evidence and bulk-index tradeoffs, not a requirement to add a bulk index. The full first-time collection has not been benchmarked.

## Collection display

View has only Visual cards and Text. Text uses compact tables with columns for quantity, name, color, printing, finish, condition, language, regular EUR price, added date and updated date. Columns use fixed widths and rows keep a consistent height within each viewport, including across groups, filtering and sorting. Long values truncate with full-value hover titles and retain complete accessible text; keyboard users can open the editor from the card-name or Edit button to read full printing details. Every data header sorts its column and toggles direction, synchronized with Sort by. Actions stay together in a sticky right-hand table column; wide tables scroll horizontally on phones. Visual cards retain fixed portrait widths.

Both views render at most 48 owned lots per page, including only that page's artwork. Filter and sort apply to the whole inventory, then groups become contiguous before paging; a group may continue on another page. Group headings count all matching copies in that group. Previous/Next and a page selector appear above and below nonempty results, alongside the visible lot range. Filtering, sorting and grouping reset to page one; switching views and revisiting Collection retain the session page. Edits/removals clamp it to the remaining pages, and reload starts on page one. Page changes return focus and scroll to the top navigation for the results.

The copy total sits directly below the display controls, separate from page navigation's lot count. Filtering shows matching copies alongside the whole-inventory total; neither count is limited to the current page. Allocation policy remains documented under Ownership and costs below rather than on the Collection browsing surface (#164/#198).

Group by offers none/type/color/set. Filter matches required terms in name/type/set. View, grouping, sorting and filter persist locally; initial settings use visual cards, no grouping and newest-added first. Old horizontal/vertical text settings migrate to Text. Legacy missing dates display a dash and use stored-order fallback. New lots record dates; edits preserve added dates.

Add owned card searches after one literal prefix character. Suggestions occupy a bounded list inside the dialog; Up/Down wrap and keep the active choice visible while focus stays in the combobox. Tab skips individual choices and continues to Cancel. Enter or pointer/touch selects a card. Escape dismisses suggestions, then closes the dialog. Its staged editor shows artwork, paginated printing choices, finish, condition and absolute quantity. Searching and selecting alone do not change holdings. Plus/minus/direct entry change drafts. Update collection applies them; Cancel/Escape/X discard them. Zero removes the selected lot.

Visual cards place the quantity badge, plus/minus and options controls on the artwork, using the deck visual controls. The options menu holds Edit and Remove, with arrow-key navigation, Escape/focus return and native outside-click dismissal. The name stays accessible through artwork labels and the menu, without a separate visible title. A single 20px caption line contains Language, Finish and Condition; overflow truncates with full hover text and editor access. Conditions use NM, LP, MP, HP and DMG; unrecorded conditions show a dash. Set, color, prices and dates remain stored and available in Text. Plus/minus changes autosave, while zero requests removal confirmation; the card editor allows direct quantity entry.

Clicking artwork, a caption or the non-control area of a Text row opens **Update card in collection** for that exact owned lot. Keyboard users can activate the artwork, the visual options menu or Text's card-name/Edit buttons. Changing printing, finish or condition keeps the chosen lot's draft quantity, rather than switching to another inventory total. **Update card** replaces the original lot with the final draft; if its new identity matches another lot, the two quantities combine with a visible explanation before saving. Changing the quantity explicitly changes the edited lot's quantity; zero removes it. Cancel/Escape discard the draft. Invalid or stale edits, merged quantities above the supported limit and failed persistence retain the original inventory. Editing preserves the original added date unless combined into an existing destination, whose added date remains; successful edits update the modification date. Add owned card and the action from global card details retain their separate inventory-entry workflow with Update collection.

The wide collection editor automatically fetches printing pages into one Version dropdown and stops at the API's final page. No manual Load more action is needed; failures preserve loaded versions and expose a retry.

At narrow widths and on non-hover/coarse-pointer devices, artwork quantity/options controls and Edit/Remove actions have at least 44×44px hit areas with separate adjacent targets. Desktop artwork controls use 36px targets, matching deck visual cards; Text keeps compact actions. These measured targets and emulated-touch checks do not establish physical-phone accuracy.

Delete entire collection is available in the Collection header. It offers a workspace backup and requires typing DELETE. It saves the empty inventory before changing the live view; a failed save retains the collection. Decks and deck budgets are preserved. There is no in-app undo; previously downloaded workspace copies remain available for restoration.

Collection data lives in browser localStorage for the exact app origin (normally http://localhost:3000), in the `arcana.workspace.v2` working copy. This same value contains decks and may use a compact representation after a quota error. Delete collection through the app to retain decks. It belongs to the current browser profile, not a file in the repository; exported workspace JSON files are separate snapshots. localhost and 127.0.0.1 use separate browser storage.

## Ownership and costs

Select any combination of Main deck, Command zone, Sideboard and Maybeboard for each deck's estimate. Main deck, Command zone and Sideboard are selected by default for new decks and older backups. The complete card table stays visible. Rows outside the estimate retain their quantities and unit prices and do not receive ownership allocations. Visual deck markers reuse these allocations before any visual filtering: outlined/filled/split indicate none/full/partial coverage. Excluded zones or missing identity use a dashed unassessed marker with an accessible explanation (#197). This does not reserve or modify inventory. An empty selection pauses the estimates. The zone selection is saved per deck and included in JSON exports.

Each deck independently allocates owned copies across selected zones in Main deck, Command zone, Sideboard, Maybeboard order, then by printing ID. Match by verified rules identity by default or by printing ID when selected; ownership is not reserved across decks. Each owned copy covers at most one demanded copy in an estimate. Deck value estimates nonbasic copies in selected zones; Cost of missing copies estimates the nonbasic copies not covered by the collection. Basic lands, including snow basics and Wastes, are excluded from costs and unpriced warnings, with copy counts and ownership intact. Deck currency offers € Euro and $ US dollar, saved per deck in complete JSON; the default is euro. Both estimates use the stored printing's selected-finish quote in that currency. Etched euro and missing quotes stay unknown. Cards, previews and printing dialogs use the same currency. Condition appraisal, shipping and tax are excluded.

Copy quantities (in selected zones, covered by collection and still needed) appear separately from monetary estimates (deck value, cheapest printings estimate and cost of missing copies). Estimates retain the priced subtotal and unpriced-copy count. The full table has sortable Card, Zone, Price per card, Copies and Cheapest per card columns. Repeated clicks reverse direction; names use natural ordering, numbers sort numerically, equal values retain their allocation order and missing quotes stay last in either direction. Sorting is session-only per deck and does not change saved entries or allocation. Cheapest cells show only the quote, set code and regular finish; scan failures and incomplete results remain visible. An exact Cardmarket product link remains available for an unpriced euro entry with a mapped product ID. Basic-land rows explicitly show their cost exclusion.

Budget targets and basis/remaining/over-budget comparisons are removed from the interface (#172). Existing valid `budgetCents` and `budgetBasis` fields are retained as inactive legacy data through loading, edits, duplication and complete deck/workspace JSON. They do not affect ownership or cost estimates. Zone selections still use the compatible `budgetZones` field. Estimate policy lives in secondary About cost estimates help; missing-price and failed/interrupted scan states remain visible on the page (#170/#173).

**Refresh €/$ prices** checks exact stored printing IDs in selected zones. Valid quotes in the selected deck currency replace the corresponding regular/foil fields, plus etched for dollars. A missing or malformed quote keeps the last usable value and a failed lookup keeps saved quotes. The timestamp describes when the app checked prices.

**Check cheapest printings** scans each verified nonbasic rules identity separately across all four zones, through every page, in the deck currency. Only completed English paper regular quotes contribute verified minima. Progress, individual errors, missing identity and completed no-quote results remain distinct. Cancel/resume and Retry incomplete scans retain completed identities and restart unfinished ones. A failed fresh check preserves its last-complete quote with a visible recheck notice; unfinished candidates never become minima. Changing currency cancels/discards these results. [Comparison boundaries](PRICE_DATA.md#current-price-coverage-and-comparison).

**Apply cheapest printings…** reviews and saves verified regular English replacements in the currently selected estimate zones. It preserves foil/etched entries, basic lands, unavailable/unfinished results and outside-scope cards. The review shows changed, already-matching and skipped copy counts, printing changes and any merging of ordered function lists. Cancellation, a changed deck/result or a failed save applies nothing. Quantities, zones, identity and function memberships survive; inventory is independent. Full [application policy](PRICE_DATA.md#current-price-coverage-and-comparison) owns eligibility and merge details.
