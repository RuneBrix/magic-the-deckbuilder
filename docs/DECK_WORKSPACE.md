# Deck library and workspace

## Section navigation and touch controls (#158 / #159)

Cards, Statistics, Ownership & costs and Checks form one keyboard tab stop. Left/Right wrap between sections with automatic activation; Home/End select the first/last section. Each tab controls a stable, labeled panel. Tab enters the active panel, then its controls; Shift+Tab returns through the panel to the selected tab. Pointer/touch selection retains the same four sections and their content.

Text-deck copy buttons and menus have at least 44×44px hit areas at narrow widths and on non-hover/coarse-pointer devices. The quantity column reserves room for both copy controls and their gap. Collection quantity and Edit/Remove controls use the same minimum touch size, while desktop hover layouts retain their compact controls. Browser geometry, accessibility-tree and emulated-touch checks do not establish physical-phone accuracy or real NVDA/browser acceptance.

## Quick add (#114)

The editor's Cards tab has a labeled **Quick add card** name search for the open deck. It shows no suggestions below three trimmed characters, waits 250 ms after typing, requests one name-sorted paper-card search page and displays at most eight choices. The query treats typed punctuation literally. New input aborts pending requests; superseded or detached responses cannot replace suggestions or add copies. Loading, no-match and lookup-failure messages stay beside the field. Empty input omits redundant destination/typing instructions (#166).

Up/Down chooses a suggestion; Enter or pointer/touch activation immediately adds one nonfoil copy of the returned printing to Main deck, with the shared automatic function default. An exact printing/finish match increments its quantity; other chosen variants remain intact. The addition is staged and saved before changing the visible deck. A failed write retains old copies and shows a retry/correction message; retry applies once. If the printing has no nonfoil version, the detailed Add card form opens with an explanation and requires a deliberate printing/finish choice. The ordinary Add/edit workflows remain available. Escape dismisses suggestions, blur hides them, and completion/cancellation returns focus to Quick add. The library does not guess a destination. Frontend changes require refreshing the existing localhost:3000 page; no server restart is needed.

## Direct card dragging (#55)

Starting a mouse drag on blank space or artwork leaves document text unselected. Start on the deck title or other text to select it. Text fields retain native selection. Deck artwork still starts the existing card move.

Selected before implementation: a drag carries **all copies in one stored deck/zone entry**. Zone drops reuse the existing validated move; destination merges retain their printing and union Functions. Dropping onto an existing Function group moves the entry into that group's zone and makes that Function primary while retaining other assignments. Both changes are staged together, so a validation failure applies neither. Dropping into the entry's current primary Function in its current zone does nothing; its overlay says Keep in current group. Type groups are never Function targets. Dropping onto Unassigned only moves zones and keeps every Function; the card may therefore appear under its retained primary Function. Command zone cards are always displayed without type/Function grouping, while retaining their stored Functions.

During a desktop mouse/trackpad drag, a full-size copy of the card follows the cursor at the grabbed point while its original is dimmed. The copy ignores pointer input and is excluded from accessibility/focus; drop, Escape, cancellation and rerenders remove it. Hover and visible keyboard focus control outlines independently of the retained preview, and pointer drops do not restore focus to the old card. Function notifications say Added [card name] to [function], without quotation marks. Each visible Function group is covered within its existing bounds by Add to [function] guidance, or Keep in current group for the source. An Add to new function drop group is always available during dragging in every layout and grouping mode. It opens the existing scoped Function-name dialog; valid submission assigns the new primary Function while preserving other Functions, copies, printing and the source zone. Cancellation and invalid input apply nothing. A fixed destination strip exposes every zone, even empty hidden Sideboard/Maybeboard; a small red-outline trash target stays at the lower right. Trash opens the existing all-zones, all-copies confirmation with Keep cards focused, and does not delete on drop. Edge scrolling must use current hit testing as the viewport moves.

The bottom strip uses equal-width destinations for zones and Add to new function, with wrapping at narrower widths. The strip stays above the dragged preview and pauses edge scrolling throughout its bounds, including the gaps. Releasing in a gap cancels the drag. Dragging along viewport edges outside the strip still scrolls the page.

Pointer-based dragging with capture is an optional desktop shortcut. The drag status names the card, copy count and source zone. Keyboard and touch use named card menus to assign Functions, move entries and confirm deletion. External payloads, stale entries, cancellation and invalid or overflowing drops leave deck data intact.

## Roles, grouping and previews

Personal roles remain the existing ordered `tags` array. **The first tag is the primary function**; entries without a first role group as Unassigned. No backup migration is needed. Editing the primary prepends it without deleting stored memberships. A blank primary uses an empty first tag as the Unassigned marker; hidden memberships still round-trip in JSON. Only primary labels appear as menu choices and in deck filtering/statistics. Inspect a card and edit its single Primary function; validated edits save immediately in the named deck context ([#25/#26 workflow](CARD_DETAILS.md)). When entries merge, existing destination roles keep their order and incoming roles are appended without duplicates.

Group by offers Type, Function and No grouping within each zone (#40). Function uses the first ordered personal role; multi-type cards keep existing category precedence (an artifact creature groups as Creature). Filter cards replaces the type/role dropdowns. It matches case-insensitive substrings across the combined card name, full type line, category, primary function (including Unassigned). Whitespace separates required terms: `elf ramp` requires both somewhere in those fields. Punctuation stays literal; there is no Scryfall syntax, phrase parser or inferred automatic function membership. Matching does not modify deck labels; #46 remains separate.

Sort by retains name A–Z, low-first mana value and most-first quantity. Price in the deck currency, Power and Toughness each offer low/high first. Power/toughness use top-level card values, or the front face when absent. Only finite numeric literals are ordered numerically. Unavailable values, including nonnumeric characteristics such as `*` or `1+*`, sort last in either direction. Zero is valid. Ties use English card name, identity/zone key and printing ID.

Type and Function headings sort alphabetically within each zone, including Land and Lands (#272). **Sort by** orders the cards inside each group. Type grouping uses the existing deck-facing card type and precedence. No grouping keeps the flat card sort, and the Command zone stays ungrouped.

All four layouts show quantity-weighted copy counts beside Type and Function headings (#90). With a filter active, group counts and group/zone prices cover only shown cards. Zone headings also retain the full-zone count. Filtering replaces only the card area so the input keeps focus and cursor position. Clear filter retains grouping and sort.

Activate a zone heading to collapse or expand its Cards content. Its heading, summary and drag destination stay available, along with the fixed drag destinations. Reopening the zone restores its nested group states. Zone disclosure is independent for each deck and zone and survives filters, layout and grouping changes, and switching away from and back to the deck during the session. Reload starts every zone expanded (#264).

Activate a group heading to collapse or expand its cards. The name, count, price and group actions stay available, with compact spacing between collapsed headings (#262). The editor remembers the state by deck, zone, grouping mode and exact group name until reload, including when filters hide a group or the player switches layouts. Renaming a group carries its disclosure state to the new name (#232, #252).

Group actions copy a plain-text list of quantities and full card names from the selected group and zone. **Copy shown cards** uses only filter matches. Collapsing a group leaves its copy scope intact. As in text export, copies with the same stored full name share a line across printings or finishes. The action returns focus to the group actions button and reports success or clipboard recovery (#212).

**Rename function group…** updates the primary label of every entry in the selected zone's group, including entries hidden by the current filter. The action appears on Function groups in Main deck, Sideboard and Maybeboard. The dialog shows the zone and total copies. Function names are trimmed and accept up to 80 characters without commas. Land, Lands and Unassigned are reserved. A name matching another primary group in the same zone is rejected regardless of case. A case-only change is allowed, and the same group name may exist in another zone. The rename replaces the old primary, keeps the order of distinct secondary labels, and saves all changes together. Cancel and save failure leave the live cards and storage intact. After saving, focus returns to the renamed group actions or to Filter cards if the renamed group is hidden. Sourced tags remain available in card details, and a new card can still receive the original automatic label. [#211](https://github.com/RuneBrix/magic-the-deckbuilder/issues/211)

Group export and the card grid use the shown entries in the selected zone. The grid displays the saved printing and copy count and returns focus to group actions on dismissal. **Remove group cards…** names the group, deck and zone and confirms the affected copies. When the filter hides group members, the confirmation defaults to shown cards and offers the whole group. Removal saves in one operation, and cancellation, a stale group or a failed write leave all entries intact. Successful removal returns focus to the group actions if still visible, or to Filter cards. Type groups continue to follow the cards' types. [#233](https://github.com/RuneBrix/magic-the-deckbuilder/issues/233)

Prices use the saved deck currency (default euro, or US dollar selected in Ownership & costs) for sorting, group/zone totals, visual captions, previews and add/edit printing dialogs. Quotes come from the stored printing and selected finish: regular/foil fields for both currencies, etched for dollars only. A missing quote never borrows another currency or finish. Basic lands, including snow basics and Wastes, remain in copy counts but are excluded from cost totals and unpriced-copy warnings. Individual previews may show an available basic-land quote; Ownership marks its cost row excluded. Group and zone amounts multiply nonbasic quotes by quantity and disclose unpriced copies. The preview uses the selected finish treatment and retains unavailable-price states. [Price policy](PRICE_DATA.md) owns preservation boundaries.

Group headers place name, copy count and cost inline in horizontal layouts, wrapping at narrow widths. Vertical layouts share header-row sizing across neighboring groups so long function names and partial-price summaries do not misalign card starts (#193). Full names, counts and unpriced status reflow rather than being clipped, including with enlarged text.

At viewport widths of 1100px and above, complete card previews use a dedicated 240px left rail aligned with the deck-card area (#42). A 28px gap separates it from editable rows. The rail starts with the card area and sticks below the measured shared header with a 20px gap while scrolling, inside the card area's bounds. Portraits keep their proportions and fit short viewports without cropping. Previewing uses the current entry's stored printing/front portrait. Visual layouts offer Flip on cards with both front and reverse images, on the visual card and large preview. Pointer/focus exit restores the front, without saving face state; text layouts omit this control. Details still exposes all available faces.

Pointer-over or keyboard focus anywhere in a row updates the shared preview, its card/zone caption, primary function, per-copy price and matching row highlight. It retains the last preview when the pointer leaves, survives ordinary rerenders, and clears when its entry is filtered out, collapsed with its zone or group, removed, moved to another key or the active deck changes. Missing artwork shows a message. Before any selection, a brief hint explains hover/focus. Touch pointer-over does not select a preview. Below 1100px the rail is hidden and the card area uses all available width. Activating the card name opens full details by mouse, keyboard or touch. Preview state is session-only and never changes saved deck data.

## Select cards

Choose **Select** beside **Filter cards** and activate card artwork or a name to select all copies of that stored printing and finish in its zone. Multiple zones can be selected together. Sorting and layout keep visible entries selected. Filtering or collapsing a zone or group drops entries it hides. Moving, removing, changing the quantity or changing the function of a selected entry drops that selection. Leaving Cards or switching decks returns to Default. Clear selection stays in Select mode. Done also returns to Default. Selection is session-only. Individual menus remain available in Select mode, and dragging uses Default mode.

The bottom Actions menu copies card names with quantities and zone headings, assigns an existing or new primary function, moves entries to a zone, adds copies to Collection, or removes the selected entries. Copying combines identical names within each zone and keeps the selection available. Assignment keeps other functions and the source zone. Moves merge identical printing/finish variants and retain the destination function order followed by any distinct source functions. Different printings remain separate, and a legacy entry with an ambiguous finish requires a choice if moving it would otherwise collide with another legacy entry. Moving out of Sideboard clears a companion designation on that entry.

Write actions show the reviewed quantities and zones and commit in one save. The review lists the selected printings and identifies exact finishes for Collection. Cancel, a stale selection and a failed save leave the workspace intact. Successful writes clear the selection. Removal affects only the reviewed entries. See [Collection workflow](COLLECTION_WORKFLOW.md#add-selected-deck-cards) for the destination lot policy. [#215](https://github.com/RuneBrix/magic-the-deckbuilder/issues/215)
