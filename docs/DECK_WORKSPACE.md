Sideboard and Maybeboard viewing sections appear only when the stored zone has entries, across all four editor layouts and the tracker. Zone totals and add/move destinations remain available, including empty zones; the fixed drag destination strip also retains every zone (#55).

Statistics places the mana curve on the left and independent card-type, personal-role and color tools on the right. Draw probability sits below the board. Labels and counts stay adjacent, and the board becomes one column at 600px.

The mana curve, total, median and average use quantity-weighted nonland mana values from Main deck and, for Commander decks, Command zone. Sideboard and Maybeboard are excluded. The histogram floors fractional mana values and groups values of seven or more in `7+`. Total, median and average use the original values across all nonlands even when the chart shows one group. Color and type breakdowns count each copy in every matching color or recognized deck-facing type. The primary-function breakdown uses the first ordered personal label, with untagged copies grouped as Unassigned. Power and toughness use numeric stored values or the front-face fallback. Missing and variable values appear under No fixed value. Rarity uses the stored printing, with missing rarity grouped as Unknown.

Draw probability uses every copy in Main deck, including lands. Each row groups copies by their first personal function or their primary deck-facing card type. The calculation samples without replacement or mulligans. It defaults to a seven-card opening hand, or fewer when the deck has fewer cards. Draws must be whole numbers between zero and the Main deck count. The requested number of matches must be between zero and the draw count. Exactly, At least and At most apply to each group independently. Statistics controls do not write to browser storage.

Statistics browser verification (#57) covers populated and empty decks, short and long function labels, independent tool heights, keyboard focus, totals and overflow in Chromium 156.0.8078.4 at 1280×900 and 390×844 in light and dark modes. GitHub tracks the remaining optional-zone and shared-navigation checks (#53 and #61). Safari and physical phone coverage remain open.

## Direct card dragging (#55)

Selected before implementation: a drag carries **all copies in one stored deck/zone entry**. Zone drops reuse the existing validated move; destination merges retain their printing and union Functions. Dropping onto an existing Function group moves the entry into that group's zone and makes that Function primary while retaining other assignments. Both changes are staged together, so a validation failure applies neither. Dropping into the entry's current primary Function in its current zone does nothing; its overlay says Keep in current group. Type groups are never Function targets. Dropping onto Unassigned only moves zones and keeps every Function; the card may therefore appear under its retained primary Function. Command zone cards are always displayed without type/Function grouping, while retaining their stored Functions.

During a desktop mouse/trackpad drag, a full-size copy of the card follows the cursor at the grabbed point while its original is dimmed. The copy ignores pointer input and is excluded from accessibility/focus; drop, Escape, cancellation and rerenders remove it. Hover and visible keyboard focus control outlines independently of the retained preview, and pointer drops do not restore focus to the old card. Function notifications say Added [card name] to [function], without quotation marks. Each visible Function group is covered within its existing bounds by Add to [function] guidance, or Keep in current group for the source. An Add to new function drop group is always available during dragging in every layout and grouping mode. It opens the existing scoped Function-name dialog; valid submission assigns the new primary Function while preserving other Functions, copies, printing and the source zone. Cancellation and invalid input apply nothing. A fixed destination strip exposes every zone, even empty hidden Sideboard/Maybeboard; a small red-outline trash target stays at the lower right. Trash opens the existing all-zones, all-copies confirmation with Keep cards focused, and does not delete on drop. Edge scrolling must use current hit testing as the viewport moves.

The bottom strip uses equal-width destinations for zones and Add to new function, with wrapping at narrower widths. The strip stays above the dragged preview and pauses edge scrolling throughout its bounds, including the gaps. Releasing in a gap cancels the drag. Dragging along viewport edges outside the strip still scrolls the page.

Pointer-based dragging with capture is an optional desktop shortcut. The drag status names the card, copy count and source zone. Keyboard and touch use named card menus to assign Functions, move entries and confirm deletion. External payloads, stale entries, cancellation and invalid or overflowing drops leave deck data intact.

## Navigation and adding cards

The header offers My decks, Explore cards and Settings at every viewport, with local-save status and Help. Startup/reload and the logo open My decks; in-session navigation preserves search (#37). Deck switching and creation belong in My decks rather than a duplicate navigation list.

Clicking library artwork or a title, and successful deck creation/import, enter the dedicated editor. It contains Cards, Statistics and Checks, plus import/export and management actions. Find cards to add explicitly tracks the editor's deck and opens discovery without clearing its search. The compact tracker names that deck and Main deck destination, with Open full deck to return. Exploration can instead track another deck or none; hiding the tracker retains the named quick-add destination. Add to… selects a different destination without changing tracking. See [Exploration](EXPLORATION.md) for #19/#20 behavior, persistence and resize controls.

The editor shows main/sideboard/command/Maybeboard counts, copy controls, zone moves and mana costs. Maybeboard is outside the playing deck; statistics, construction checks and brackets exclude it. Zone moves transfer every copy and merge roles without deleting data on overflow. Commander identity is the union of designated command-zone card identities, not proof of eligibility; other formats show the main-deck identity, excluding sideboard cards.

## Compact presentation (#38 / #39)

Library cards lead with landscape artwork and open through either their artwork or title. The first designated command-zone card supplies the cover even when a main-deck card was added first. Without a designation, the first main-deck card with a usable portrait supplies it; otherwise the existing card mark is shown. Multiple commanders use the first command-zone entry. Use the stored printing's Scryfall `art_crop`, including its first face when present, before a CSS portrait crop fallback. The fallback uses `object-fit: cover` at 25% vertical position; unusual/full-art frames can differ. No new image source, extra card-data request or saved-data migration is required. The normal portrait remains available in card details.

Covers use a 16:10 landscape frame with a 176px minimum; the information area grows with its content from a 132px minimum. Title, centered color markers and bracket text stay together with 10px gaps. Long titles display at most two lines while retaining their full accessible name. The library grid reserves columns for additional decks rather than stretching a single cover across the page. Named color-identity mana symbols show letters as well as game colors; commander-not-designated and colorless states remain explicit. Listings omit card/land/average-mana statistics, redundant identity wording and the separate Open deck button. Bracket text is only the assignment or No bracket assigned. Management stays in a named ⋮ disclosure.

The editor uses available page width with a top-left title, visible Find cards to add and a shared management menu. Capitalized format, counts, color symbols and a quieter Commander bracket selector wrap beneath the title. The header omits Command-zone identity wording. Bracket discussion guidance opens Checks, scrolls to the discussion and focuses it for keyboard/screen-reader use. Assignment remains personal; freshness, source limits and unsupported rules remain visible in Checks. Deck-card layouts, controls, previews and menus are implemented in #40–#43.

## Roles, grouping and previews

Personal roles remain the existing ordered `tags` array. **The first tag is the primary function**; entries without a first role group as Unassigned. No new metadata or backup migration is needed. Inspect a card and edit its comma-separated roles to change their order; validated edits now save immediately in the named deck context ([#25/#26 workflow](CARD_DETAILS.md)). When entries merge, existing destination roles keep their order and incoming roles are appended without duplicates.

Group by offers Type, Function and No grouping within each zone (#40). Function uses the first ordered personal role; multi-type cards keep existing category precedence (an artifact creature groups as Creature). Filter cards replaces the type/role dropdowns. It matches case-insensitive substrings across the combined card name, full type line, category, primary function (including Unassigned) and every personal role, including secondary roles. Whitespace separates required terms: `elf ramp` requires both somewhere in those fields. Punctuation stays literal; there is no Scryfall syntax, phrase parser or inferred automatic function membership. Matching does not modify deck labels; #46 remains separate.

Sort by retains name A–Z, low-first mana value and most-first quantity. Price USD, Power and Toughness each offer low/high first. Power/toughness use top-level card values, or the front face when absent. Only finite numeric literals are ordered numerically. Unavailable values, including nonnumeric characteristics such as `*` or `1+*`, sort last in either direction. Zero is valid. Ties use English card name, identity/zone key and printing ID.

Entries sort before grouping, and groups follow their first included entry. All four layouts show quantity-weighted copy counts beside prominent Type and Function headings (#90). With a filter active, group counts and group/zone prices cover only shown cards. Zone headings also retain the full-zone count. Filtering replaces only the card area so the input keeps focus and cursor position. Clear filter retains grouping and sort. These session controls leave stored cards, printings, quantities, functions, statistics and Checks unchanged.

Prices use stored per-copy USD quotes for the selected printing (#94/#95). Use `prices.usd` for regular printings or legacy records without finish metadata, `usd_foil` for foil-only printings and `usd_etched` for etched-only printings. Missing or invalid quotes and ambiguous foil/etched finishes count as unpriced. Group and zone amounts multiply by quantity and label known subtotals and unpriced copy counts separately. Cards uses these same quotes for sorting and previews. Ownership & budget has a separate [EUR estimate](COLLECTION_BUDGETS.md).

At viewport widths of 1100px and above, complete card previews use a dedicated 240px left rail aligned with the deck-card area (#42). A 28px gap separates it from editable rows. The rail starts with the card area and sticks 20px from the viewport top while scrolling, inside the card area's bounds. Portraits keep their proportions and fit short viewports without cropping. Previewing uses the current entry's stored printing/front portrait; details still exposes all available faces.

Pointer-over or keyboard focus anywhere in a row updates the shared preview, its card/zone caption, primary function, per-copy price and matching row highlight. It retains the last preview when the pointer leaves, survives ordinary rerenders, and clears when its entry is filtered out, removed, moved to another key or the active deck changes. Missing artwork shows a message. Before any selection, a brief hint explains hover/focus. In visual stack views, hovering or focusing a card also reveals its name, set code and per-copy price below the artwork. Touch pointer-over does not select a preview. Below 1100px the rail is hidden and the card area uses all available width. Activating the card name opens full details by mouse, keyboard or touch. Preview state is session-only and never changes saved deck data.

## Creation, management and interoperability

All seven existing format presets remain available. New Commander decks offer a card-name lookup and optional designation. Choose later creates an incomplete deck; choosing a card puts one copy in the command zone. Search results are not an eligibility filter, and designation does not validate pairings or special commander rules (#13). Other formats ignore the commander selection.

Library and editor ⋮ disclosures contain Rename / format, Import cards, Export deck, Duplicate and Delete deck. Native Enter/Space and Tab work alongside Arrow Up/Down, Home/End and Escape; Escape returns focus to the trigger, outside clicks dismiss the disclosure, and launching an action closes it before opening a dialog. Actions target the named deck. Rename/format edits target that deck. Duplicate deep-copies every card, quantity, zone and ordered role into an independent deck with a new ID. Delete names its target and opens a deliberate confirmation with Keep deck focused first. Existing workspace/deck entry/copy limits still apply.

The library can import a new text decklist or add text cards to a named deck. Existing-deck imports merge atomically; new-deck imports commit only after all cards resolve and limits pass. Failed or dismissed imports retain existing data. Heading-aware text imports/exports preserve names, quantities and zones, but do not promise personal roles or printing preservation. Export also offers a complete single-deck JSON backup, compatible with Settings → Restore JSON backup. JSON preserves ordered roles, stored card data, zones and player-assigned Commander brackets. Text decklists do not preserve assigned brackets. See [bracket discussion](COMMANDER_BRACKETS.md) for assignment, conditional guidance and source freshness. Settings still provides a complete workspace backup. Expanded external-format support remains #6.

## Four views and card actions (#41 / #43 / #44)

View offers Horizontal visual stacks (default), Vertical visual stacks, Horizontal text and Vertical text. Horizontal cards have vertically arranged groups; vertical cards have horizontally arranged groups. Vertical text uses three equal-width group slots on desktop, including when only one group is present; groups wrap into new rows without a horizontal scroller. Horizontal text uses the same full-width three-column grid for entries. Both text layouts use two columns at widths up to 1000px and one up to 600px. Zones display Command zone, Main deck, Sideboard, then Maybeboard in every view. Type/Function/No grouping, filtering and sorting apply consistently. View selection is session-only. Visual cards use 28px palette-colored triangular quantity badges entirely inside the top-left corner, with matching 7px rounding and optically centered Public Sans numerals (11px, or 9px for three digits), clear of the card name, with plus, minus and options controls on solid palette surfaces down the right side (#91). Artwork begins at the card top without reserved toolbar space. Controls retain accessible names, hover outlines and visible keyboard focus; visual tab order follows plus, minus, options. All three side controls share 36px-square desktop bounds and 44px-square phone/non-hover bounds. Counter colors use the selected appearance accent and its matching foreground. Text controls are unchanged. Horizontal cards remain 190px wide with 8px gaps while they fit. Resting slot positions reserve the full reveal distance: in dense groups the advance is `(available width - 2 × card width - gap) / (entry count - 2)`, capped at card width plus gap. Hover or visible keyboard focus translates only following slots to the right; preceding slots and the selected card stay fixed. There is no gap redistribution, width animation, mouse-move handler or timer. Keyboard focus takes priority over a resting pointer. Vertical stacks use the same following-only reveal downward, with fixed 48px resting advances. Complete portraits remain behind following cards; opening a card reveals its side controls and artwork with an 8px gap. Each visual card has a named keyboard focus stop. The solid backing and contrasting borders keep the centered SVGs distinct from artwork. Hover changes the backing, and keyboard focus adds an outer outline. Inherited group margins are removed and zones use a 20px gap. Text entries use a compact single row with matching 13px quantity/name text and inline mana costs; names truncate with an ellipsis before mana costs and retain their full accessible name and hover title. Visual groups never scroll horizontally; vertical visual groups wrap into new rows. At phone widths or on non-hover devices, both visual views wrap full cards instead of overlapping; visual menu and quantity targets are 44px square. The existing left preview and full details remain available.

Each entry has a named ⋮ menu using the browser's viewport-constrained top-layer popover. The visible header shows only the card name; the menu’s accessible name retains card/deck/zone context. Function and Move to open beside the main menu and list only actionable options. Move to transfers the entire entry to the selected zone. Hovering an option opens its flyout without moving keyboard focus; leaving both the option and flyout closes that hover-only panel. The adjoining panels have no pointer gap. Clicking a parent option does not pin its flyout: mouse departure still closes it, and hovering another option switches panels. Taps provide access on non-hover devices. Right/Enter/Space enter a submenu without making mouse clicks persistent; Up/Down and Home/End navigate the focused panel, and Left/Escape closes the flyout and focuses its parent. Escape at the top level restores the card trigger; Tab and outside activation dismiss both panels. Moves and saved function/copy forms restore focus to the surviving card trigger when visible. Flyouts flip left when needed and both panels narrow to fit small viewports. Long menus scroll internally; menus dismiss on page scrolling and reposition when the viewport resizes. Phone targets are at least 44px high. Stale entries cannot redirect an operation to another deck.

In the deck editor, tracker and card details, minus asks for confirmation before removing the last copy of a Command zone entry. Keep commander or Escape preserves the deck. Remove commander affects only the named deck and entry. Decrements that leave the entry in place apply immediately.

- Assign card to function… lists this deck’s existing labels and marks the current primary Function. Activating a label assigns it immediately as the first ordered role while retaining other roles. Add new function… opens an overlay with one name field; Create and assign validates and assigns to the card/deck/zone that opened it. Blank, oversized or comma-containing names leave data unchanged and show an inline error. Labels remain private entry metadata, with no unused-label catalog or automatic classification (#46).
- Move to… lists the other zones, including empty Sideboard/Maybeboard destinations. Selecting one transfers all copies of the entry. A merge keeps the destination printing and unions Functions; overflow aborts atomically.

- Copy card name copies only the name. Open details retains the exact entry context; [explicit details targets and quantities (#45)](CARD_DETAILS.md) remain available.
- Delete card explicitly spans every copy in every zone of the named deck, including Maybeboard, using the card's stored Oracle identity (printing ID fallback). A confirmation lists quantities by zone and initially focuses Keep cards. Cancelling leaves every copy intact. Quantity +/− stays inline.

Maybeboard survives reload, duplication and complete JSON restore, with quantities, functions and stored printing. Sectioned text uses a `Maybeboard` heading and preserves names/quantities/zones; roles, printing, commander flags and brackets still require JSON. Existing saved decks and legacy backups remain compatible. Exploration's Add to… chooser also offers every zone without changing the tracked deck.

Type groups, deck type/subtype filtering and primary type statistics use a shared deck-facing type policy, including Battle/Conspiracy and multitype priorities (#62). Complete card/face facts and printing choices remain stored unchanged. [Face/layout policy and verification](CARD_TYPES.md).
