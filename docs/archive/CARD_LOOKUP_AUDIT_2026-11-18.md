# Card lookup audit — 18 November 2026

Evidence for [#226](https://github.com/RuneBrix/magic-the-deckbuilder/issues/226). This is a dated workflow audit, not a live Scryfall completeness claim. The source map and current feature contracts remain authoritative. All checks use synthetic cards and mocked upstream replies; personal browser data is untouched.

| Workflow | Findings and verification |
| --- | --- |
| Explore and Quick add | Discovery deliberately permits broad matches, followed by explicit card selection. Existing search/details and Quick add browser checks cover selection, stale replies, cancellation, nonfoil-only Quick add, foil fallback and reload. Audit checks distinguish endpoint 404s from genuine no-card replies for name suggestions. |
| Commander creation | Search selection retains its exact card and ordinary supported finish default. Native creation/stale-autocomplete tests and browser library checks retain this behavior. New-deck saves now stage before adding to the library; an audit regression reproduces rejected writes. |
| Deck text import | Exact full/face-name resolution rejects missing and ambiguous identities; the name-based printing contract remains intentional. New and existing destinations now persist before applying, with a once-only retry guard. Audit checks cover rejected writes, incomplete results, cancellation, changed lists and 151 names in three requests (75/75/1), retaining an etched double-faced card and its zone through reload. Existing parser/zone tests cover suffix discard, exact face names and same-name identity conflicts. |
| Details and deck printing changes | Existing pagination, same-page retry, detached-dialog and reversible-printing validation remain in place. Detailed Add, cross-deck copy and printing edits now use staged persistence. Native and browser checks cover selected finishes, exact entries, retained functions, cancellation, failure and retry. |
| Collection manual Add/Edit | Found unrestricted finish choices, unvalidated printing pages and live changes before failed new-lot saves. Loaded pages now validate identity before advancing pagination; finish options follow known metadata and preserve saved choices. Regressions cover regular/foil-only/etched-only defaults, unsupported choices, unrelated replies, absolute quantities and rejected writes. Browser checks cover long double-faced names, edition/collector/language, cancel, keyboard retry and reload. |
| Collection upload | Found fallback lookup assuming nonfoil for omitted finishes, cache sharing between omitted and explicit finish rows, and early selection before all identity pages were read. Fallback now checks all pages, prefers nonfoil when available, separates finish policies and rejects cross-page identity ambiguity. Later-page failure blocks applying and retries completed pages from cache. Edition/collector/language constraints remain deliberate until an explicit replacement. Native checks cover normalized edition punctuation/spacing, suffix 12a beyond page one, wrong set/language, missing names, unsupported finishes and manual recovery. |
| Ownership and prices | Existing allocation and owned-printing tests cover identity/finish/language, quantities, splits, merging, cancel, stale reviews and failed saves. Cheapest-price checks already require complete eligible identity scans, preserve completed work and reject partial minima. Exact-ID price refresh now also rejects conflicting identities and stages facts before saving. |
| Legality refresh | Existing tests cover partial replies, missing formats, same-name identities, reversible faces, stale/removed/replaced entries, batching and retry. Rejected persistence now retains prior card facts and reports failure rather than claiming freshness. |
